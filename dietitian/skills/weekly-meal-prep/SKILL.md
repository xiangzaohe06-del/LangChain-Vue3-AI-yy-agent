# 多日菜单与备餐

1. 确认计划天数、人数、每天包含几餐、预算范围、厨具与储存条件。缺失非关键条件时明确给出示例假设，不一次追问所有细节。读取用户已保存的忌口和过敏，以当前澄清为准。
2. 先确定每天主食、蛋白质来源与蔬菜的搭配，再安排具体菜式；在食材复用与菜式变化之间平衡，优先利用用户已有食材。涉及具体菜谱选择或比较时，可再加载recipe-recommendation。
3. 本轮知识库足够时直接使用，缺少具体资料时调用search_knowledge；需要补充公开菜谱时再使用web_search。涉及储存时长、特殊人群或食品安全的具体建议应检索适用资料；查不到就说明限制，不凭空给所有菜统一保质期。
4. 用菜单表列出每天各餐，再汇总去重采购清单；按人数和计划份数合计数量，区分已拥有与需采购。价格只作有依据的估算，注明地区和价格不确定性，不声称保证预算精确达成。
5. 给出分批采购与备餐顺序、可复用的半成品和当天完成的步骤。根据食材和设备安排冷藏/冷冻，不默认一周熟食全部冷藏；提醒生熟分开、及时冷却和食用前适当加热，必要时引用食品安全来源。
6. 输出控制在用户所需细节：菜单、采购量、备餐安排、关键限制与来源。不要擅自把本次计划写成长期记忆；仅在用户明确要求时调用记忆工具。
